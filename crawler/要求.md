# 美团网页版评论爬虫实现要求

## 1. 任务目标

基于已有的美团网页版店铺与商品采集需求，补充一套明确的爬虫运行要求。

本次重点要求是：使用 Playwright 操作美团官网页面，在用户当前浏览器页面或当前页面标签中完成必要的数据采集准备，通过串行、低并发方式探索页面所需接口，并爬取当前页面下可访问的全部评论数据。

最终爬虫应支持：

- 打开美团官网；
- 如需登录，暂停并提醒用户手动登录；
- 只在当前页面标签内操作；
- 不额外拉起新的浏览器窗口或新标签；
- 不依赖大量 UI 点击；
- 串行、低并发地探索和调用必要接口；
- 爬取当前页面所有评论；
- 支持断点续爬；
- 采集结果及时写入文件，避免中途失败导致数据丢失。

## 2. Playwright 使用要求

必须使用 Playwright 作为浏览器自动化与页面上下文控制工具。

要求：

- 优先连接或复用当前已打开的浏览器上下文；
- 只操作当前页面标签；
- 不主动新开浏览器；
- 不主动新开标签页；
- 不在多个标签之间跳转采集；
- 不通过大量 UI 点点点完成采集；
- 页面操作只用于必要的初始化、登录确认、页面状态检查和接口探索；
- 数据采集优先基于页面中的网络请求、接口响应或页面上下文可获取的数据。

如果页面必须登录才能继续：

1. Playwright 打开或定位到美团官网页面；
2. 检测到登录态缺失；
3. 暂停自动流程；
4. 明确提示用户：请在当前页面手动登录；
5. 用户完成登录后，继续后续采集流程。

## 3. 页面操作边界

爬虫只能在当前页面标签中执行，不允许额外创建新的浏览器页面或标签。

允许的操作：

- 在当前标签打开美团官网；
- 在当前标签中等待页面加载；
- 在当前标签中读取 DOM 信息；
- 在当前标签中监听网络请求和响应；
- 在当前标签中执行必要的页面脚本；
- 在当前标签中滚动页面以触发正常懒加载；
- 在当前标签中等待用户完成登录、定位、验证码等人工动作。

不允许的操作：

- 新开浏览器窗口；
- 新建标签页；
- 批量打开多个店铺页；
- 高频刷新页面；
- 自动绕过登录、验证码或风控；
- 通过攻击性或异常请求方式抓取数据；
- 用大量 UI 点击模拟人工逐条翻页。

## 4. 接口探索要求

应根据当前页面的真实网络行为，串行、低并发地探索评论数据相关接口。

探索方式：

- 监听当前页面的 network request 和 response；
- 识别与评论、评价、商品详情、店铺详情相关的接口；
- 记录接口 URL、请求方法、请求参数、分页参数、响应结构；
- 优先复用当前页面已有请求上下文；
- 不盲目扫描接口；
- 不暴力枚举参数；
- 不并发打接口。

探索目标：

- 找到评论列表接口；
- 找到分页方式；
- 找到评论总数或是否还有下一页的判断字段；
- 确认评论字段结构；
- 确认接口是否需要登录态、定位信息、token、签名或页面上下文参数；
- 确认接口返回失败、空数据、限流时的表现。

## 5. 评论采集范围

需要爬取当前目标页面下可访问的所有评论。

评论范围包括但不限于：

- 店铺评论；
- 商品评论；
- 用户评价列表；
- 评分明细；
- 评论标签；
- 有图评论；
- 追评或补充评价，如页面可见；
- 商家回复，如页面可见。

如果当前页面只能访问部分评论，则采集当前登录状态和页面权限下能正常访问的评论，不绕过访问限制。

## 6. 评论字段要求

每条评论尽可能采集以下字段：

- 评论 ID；
- 店铺 ID；
- 店铺名称；
- 商品 ID；
- 商品名称；
- 用户昵称；
- 用户头像；
- 评分；
- 评论内容；
- 评论时间；
- 评论图片；
- 评论视频，如有；
- 评论标签；
- 规格或购买商品信息；
- 口味评分；
- 包装评分；
- 配送评分；
- 商家回复内容；
- 商家回复时间；
- 是否匿名；
- 是否有图；
- 原始接口数据；
- 采集时间。

如果不同接口返回字段不一致，应保留原始响应中的完整字段，避免数据丢失。

## 7. 串行与低并发要求

爬虫必须采用保守采集策略。

要求：

- 默认串行请求；
- 同一时间只处理一个评论分页请求；
- 每次请求之间加入合理等待；
- 不使用高并发；
- 不使用线程池批量请求；
- 不短时间内重复请求同一接口；
- 遇到异常、限流、空响应时自动降速；
- 必要时暂停并等待用户确认。

建议策略：

- 每页评论请求间隔不少于 1 到 3 秒；
- 失败后指数退避；
- 连续失败达到阈值后暂停；
- 保存失败页码和失败原因，便于后续续爬。

## 8. 断点续爬要求

爬虫必须支持断点续爬。

运行过程中需要维护进度状态文件，例如：

- 当前店铺；
- 当前商品；
- 当前评论接口；
- 当前页码或游标；
- 已完成页码；
- 已采集评论 ID；
- 最近成功采集时间；
- 失败次数；
- 失败原因；
- 下一次应从哪里继续。

建议状态文件：

- `outputs/state.json`

断点续爬规则：

- 启动时优先读取已有状态；
- 如果存在未完成任务，从上次成功位置继续；
- 已采集过的评论不重复写入；
- 如果同一评论重复出现，以评论 ID 去重；
- 如果没有评论 ID，则使用店铺、商品、用户、时间、内容摘要组合去重；
- 每完成一页或一批评论后立即更新状态文件；
- 程序异常退出后，下次启动能继续。

## 9. 及时写入要求

采集结果必须及时写入，不能全部放在内存中等结束后一次性保存。

要求：

- 每采集到一页评论，就写入一次结果文件；
- 写入成功后再更新进度状态；
- 文件写入使用追加模式或安全覆盖模式；
- 避免重复数据；
- 保留原始响应数据，方便后续补字段；
- 程序中断时，已采集数据不能丢失。

建议输出文件：

- `outputs/comments.jsonl`：每行一条评论，便于追加写入和断点续爬；
- `outputs/comments.xlsx`：任务完成后再汇总导出；
- `outputs/raw/`：保存关键接口原始响应；
- `outputs/state.json`：保存断点续爬状态；
- `outputs/errors.jsonl`：保存失败页、异常和接口错误。

## 10. 登录与人工介入要求

如果出现以下情况，需要暂停并提醒用户处理：

- 未登录；
- 登录已过期；
- 需要选择城市或定位；
- 出现验证码；
- 页面弹出安全验证；
- 当前页面没有评论权限；
- 接口返回明显风控或访问限制。

提醒方式应清楚说明：

- 当前卡在哪一步；
- 用户需要在当前页面完成什么操作；
- 完成后如何继续；
- 已经保存到哪里；
- 下次是否可以续爬。

## 11. 错误处理要求

需要处理以下异常：

- 页面加载失败；
- 网络请求失败；
- 接口返回空数据；
- 接口返回结构变化；
- 分页参数失效；
- 登录态失效；
- 请求被限流；
- 评论字段缺失；
- 写入文件失败；
- 状态文件损坏；
- 程序中途退出。

处理原则：

- 单页失败不丢弃已采集数据；
- 单条评论字段缺失不影响其他评论；
- 接口结构变化时保存原始响应并记录错误；
- 连续失败时停止继续请求，避免触发更强限制；
- 状态文件损坏时备份损坏文件，再从已写入结果中恢复进度。

## 12. 合规与安全要求

采集仅限用户当前页面和当前登录状态下能够正常访问的数据。

必须遵守：

- 不绕过登录；
- 不绕过验证码；
- 不绕过访问权限；
- 不破解签名或加密机制；
- 不高频请求；
- 不压测网站接口；
- 不干扰美团服务；
- 不采集页面无法正常访问的数据。

如果平台规则或页面提示不允许采集，应停止相关操作。

## 13. 与原始需求的关系

`需求.md` 主要描述要采集哪些店铺、商品、分类和商品详情字段。

本 `要求.md` 主要补充实现和运行约束，尤其是：

- Playwright 的使用方式；
- 只在当前页面标签操作；
- 登录时需要用户手动处理；
- 不额外拉起浏览器；
- 不使用大量 UI 点击；
- 串行、低并发探索接口；
- 当前页面所有评论采集；
- 断点续爬；
- 及时写入。

后续实现爬虫时，应同时遵守 `需求.md` 和 `要求.md`。
