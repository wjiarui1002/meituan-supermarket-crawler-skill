# 美团网页版店铺与商品信息爬取需求

## 1. 需求目标

打开美团网页版，由用户在搜索框中指定搜索关键词。系统根据该关键词完成搜索，进入目标店铺页面，并爬取该店铺的基础经营信息、商品分类信息，以及各分类下商品的详细信息。

最终目标是形成一份结构化数据，能够清楚展示：

- 搜索关键词对应进入了哪些店铺；
- 每个店铺的评分、月售、商家电话等基础信息；
- 每个店铺下有哪些商品分类；
- 每个分类下有哪些商品；
- 每个商品的图片、名称、销量、价格、评价和商品详情字段。

## 2. 使用流程

1. 打开美团网页版。
2. 用户在美团搜索框中输入指定关键词。
3. 系统根据搜索结果进入店铺。
4. 对进入的店铺采集店铺基础信息。
5. 遍历店铺内的商品分类。
6. 遍历每个分类下的商品列表。
7. 进入商品详情或展开商品信息区域，尽可能采集完整商品字段。
8. 将采集结果保存为结构化文件。

## 3. 用户输入

用户需要提供：

- 搜索关键词：例如品类、菜品、店铺名、商圈等。
- 目标范围：
  - 只爬取搜索结果中的第一个店铺；
  - 或爬取搜索结果中的前 N 个店铺；
  - 或由用户手动指定进入某个店铺后再开始采集。
- 输出格式偏好：
  - Excel；
  - CSV；
  - JSON；
  - 或同时输出多种格式。

## 4. 店铺信息采集字段

进入店铺后，需要爬取以下店铺级字段：

- 店铺名称；
- 店铺评分；
- 月售数量；
- 商家电话；
- 店铺地址，如页面可见；
- 起送价，如页面可见；
- 配送费，如页面可见；
- 配送时间或营业时间，如页面可见；
- 店铺公告或商家描述，如页面可见；
- 店铺链接；
- 采集时间。

其中，明确必采字段为：

- 评分；
- 月售；
- 商家电话。

其他字段属于页面有则采集，没有则留空。

## 5. 商品分类采集字段

需要爬取店铺内所有可见商品分类，例如：

- 热销；
- 折扣；
- 套餐；
- 主食；
- 饮品；
- 小吃；
- 招牌；
- 其他店铺自定义分类。

每个分类需要记录：

- 分类名称；
- 分类排序；
- 分类下商品数量；
- 所属店铺名称；
- 所属店铺链接。

## 6. 商品基础信息采集字段

每个分类下的每个商品，需要尽可能采集以下字段：

- 商品所属分类；
- 商品图片；
- 商品名称；
- 销售数量；
- 原价；
- 现价；
- 折扣信息，如页面可见；
- 商品评价；
- 商品评分，如页面可见；
- 商品标签，如热销、招牌、新品、折扣等；
- 商品链接或详情入口，如页面可获取；
- 商品是否售罄；
- 商品规格信息，如页面可见；
- 商品库存信息，如页面可见。

## 7. 商品详细信息采集字段

商品详情中需要尽可能爬取所有可见字段。包括但不限于：

- 商品属性；
- 掌柜描述；
- 主料；
- 辅料；
- 口感；
- 制作方法；
- 包装特色；
- 制作时长；
- 荤素；
- 分量；
- 口味；
- 适用人数；
- 净含量；
- 规格；
- 过敏原提示；
- 储存方式；
- 其他页面展示的商品说明。

原则是：商品详情里有多少字段就采集多少字段，不限定只采集固定字段。

如果详情信息是动态字段，应保存为键值对结构，例如：

```json
{
  "主料": "牛肉、米饭",
  "辅料": "洋葱、青椒",
  "口味": "微辣",
  "分量": "1人份"
}
```

## 8. 推荐输出结构

建议输出两类数据：

### 8.1 店铺表

每一行代表一个店铺。

字段示例：

- search_keyword；
- shop_name；
- shop_rating；
- monthly_sales；
- shop_phone；
- shop_address；
- delivery_fee；
- min_order_amount；
- business_hours；
- shop_notice；
- shop_url；
- crawled_at。

### 8.2 商品表

每一行代表一个商品。

字段示例：

- search_keyword；
- shop_name；
- shop_url；
- category_name；
- category_order；
- product_name；
- product_image；
- sales_count；
- original_price；
- current_price；
- discount_info；
- product_review；
- product_rating；
- product_tags；
- sold_out；
- product_url；
- product_detail_json；
- crawled_at。

其中 `product_detail_json` 用于保存商品详情中的动态字段，避免因为不同商品字段不一致导致数据丢失。

## 9. 数据保存要求

图片字段优先保存图片 URL。

如后续需要下载图片，可额外保存到本地目录，并在商品表中记录：

- 图片原始 URL；
- 本地图片路径；
- 下载状态。

数据文件建议保存到：

- `outputs/shops.xlsx`；
- `outputs/products.xlsx`；
- `outputs/raw/`，用于保存原始页面数据或调试数据；
- `outputs/images/`，用于保存下载后的商品图片。

## 10. 运行与交互要求

由于美团网页可能存在登录、定位、验证码、动态加载和风控机制，初始版本建议采用半自动流程：

1. 用户先在浏览器中正常打开美团网页版；
2. 如需要登录、选择城市、授权定位或处理验证码，由用户手动完成；
3. 用户输入搜索关键词；
4. 系统从当前可访问页面开始采集公开可见数据；
5. 遇到加载失败、弹窗或验证码时，暂停并提示用户处理。

## 11. 异常处理要求

需要考虑以下情况：

- 搜索结果为空；
- 店铺页面无法打开；
- 店铺没有展示商家电话；
- 店铺商品分类为空；
- 商品图片懒加载失败；
- 商品详情需要点击后才显示；
- 页面滚动后才加载更多商品；
- 价格、销量、评价字段缺失；
- 美团页面结构变化；
- 触发验证码或访问限制。

处理原则：

- 单个字段缺失时，不中断整体采集，字段留空；
- 单个商品采集失败时，记录失败原因并继续下一个商品；
- 单个店铺采集失败时，记录失败原因并继续下一个店铺；
- 触发验证码、登录失效或明显风控时，暂停采集并提示用户手动处理。

## 12. 合规与限制

本需求只针对用户在浏览器中可以正常访问和查看的公开页面数据进行整理采集。

实现时需要注意：

- 不绕过登录、验证码、付费墙或访问控制；
- 不进行高频请求；
- 不攻击、干扰或破坏网站服务；
- 尽量模拟正常用户浏览节奏；
- 如美团平台规则不允许相关采集，应以平台规则为准。

## 13. 当前需求理解总结

你的意思是：你指定一个美团搜索关键词，我帮你从美团网页版搜索并进入店铺，把店铺层面的评分、月售、电话采下来；然后继续把店铺里的商品分类全部遍历一遍，把每个分类下商品的图片、名称、销量、原价、现价、评价和详情信息尽量完整采下来。商品详情字段不是固定死的，只要页面里展示了属性、描述、主料、辅料、口感、制作方法、包装特色、制作时长、荤素、分量、口味等信息，都要尽可能保存下来。

后续实现时，推荐先做一个半自动浏览器采集工具：你负责在浏览器里完成登录、定位、验证码和关键词指定，工具负责从页面中提取并导出结构化数据。
